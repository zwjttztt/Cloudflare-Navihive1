# 全站弹窗排查与评估报告（2026-10-16）

**范围**：站内全部 19 个对话框 / 覆盖层 × 4 档视口（1440 / 1024 / 768 / 375，高度 800）。
**方法**：真 Chrome（headless，CDP）驱动本地自托管实例，逐个人工点开每个弹窗，
量纸面尺寸、越界、内容裁切、按钮行、正文与操作区关系，并在测量前把可滚区域滚到底
（MUI v9 的 DialogActions 是 `position: sticky`，「内容初始伸到操作区下面」是设计行为，
真正的判据是滚到底之后最后一项露不露得出来）。

复现工具（在仓库外，`Claw/harness/`）：
`audit-drive.mjs`（两段式：登录 → 重新导航 → 跑走查）+ `audit-dialogs.mjs`（19 个弹窗的
打开/测量/关闭）+ `run-audit.sh <宽> <高> <输出.json>`，原始数据 `harness/out/audit-*.json`。

## 一、结论速览

| 分级 | 数量 | 摘要 |
| --- | --- | --- |
| P1 功能性 | **1** | **记事本入口在 <900px 视口完全不可达**（不是样式问题，是功能缺失） |
| P2 体验性 | 2 | 网站设置的图标 API 帮助文字在 375 下溢出 16px；卡片设置在 375 下操作区换行成 116px 高 |
| P3 建议性 | 3 | 网站设置内容总高 3230px（375 下 5 屏+）；单卡删除无二次确认仅靠 8 秒撤销；部分弹窗内容与 maxWidth 不匹配 |
| 正向结论 | — | 19 个弹窗在 4 档视口下**均无横向溢出、无按钮行溢出、无页面横向滚动**；标题/按钮布局高度一致 |

除上述条目外，弹窗体系的底子是好的：统一外壳（`dialogShell.ts` 的标题/正文/操作三区）、
破坏性按钮一律放左侧、确认放右侧、口令类输入框已全部改用「text + CSS 遮蔽」、
输入框 `autoComplete` 已治理过一轮。下面按「问题 → 根因 → 位置 → 建议」展开。

## 二、问题清单

### P1-1　记事本入口在窄屏完全不可达（功能缺失，不是样式问题）

- **现象**：视口宽度 < 900px（md）时，顶栏「记事本（N）」按钮被 `display: { xs: "none", md: "inline-flex" }` 隐藏；
  底部胶囊导航只有 搜索 / 分组 / 新增 / 更多 / 星标；「更多选项」菜单 9 项里没有记事本；
  命令面板（Ctrl+K）20 条命令里也没有。**手机上没有任何入口能打开记事本。**
- **根因**：`src/components/HeaderActions.tsx:232` 与「新增 / 更多」共用同一套显示门槛，
  而那两个动作在底部导航有对应入口，记事本没有——门槛照搬了，兜底入口没搬。
- **复现**：把窗口缩到 899px 以下，页面上找不到任何「记事本」字样（搜索框搜「记事本」也无入口）。
- **影响**：手机 / 分屏 / 窄窗口用户完全用不了记事本（含里面的分享、版本历史、关系图）。
- **建议**（任选其一，推荐 A）：
  - **A. 底部导航加一项「笔记」**：`MobileTabBar` 的 items 数组加 `{ key: "notes", label: "笔记", icon, onClick: onOpenNotes }`，
    同时把现有 5 项改成分发式（`onNotes` 由 App 的 `setNotesOpen(true)` 提供，见 `App.tsx:1559`）。
    底部导航现在 5 项，加到 6 项在 375 下每项约 56px，仍够点。
  - B. 把顶栏按钮的门槛从 `md` 降到 `xs`（图标 + 数字角标即可，文案「记事本（N）」在窄屏会挤）。
  - C. 在「更多选项」菜单加一项「记事本」——改动最小，但入口深，适合作为 A/B 的补充。

### P2-1　网站设置：图标 API 帮助文字在 375 下溢出 16px

- **现象**：`site.iconApi` 字段的 helperText「域名字符串用 {domain} 占位，例：https://www.faviconextractor.com/favicon/{domain}」
  在 375 视口下比容器宽 16px——那段 URL 没有空格，不断行，文字伸出输入框右缘（见下图）。
- **根因**：长 URL token 不断行；MUI 的 `FormHelperText` 默认只在空白处换行。
- **位置**：`src/components/SettingsDialog.tsx:574`（`site.iconApi` 的 `helperText`）；
  相邻的 `site.thumbApi`（`:588`）的 helperText 也有长 token，同一病灶。
- **建议**：给这两个 `TextField` 加
  ```tsx
  sx={{ "& .MuiFormHelperText-root": { overflowWrap: "anywhere", wordBreak: "break-word" } }}
  ```
  更彻底的打法是在 `dialogShell.ts` 的 `dialogContentSx` 里统一加这条规则，
  一次覆盖所有用公共外壳的弹窗（本弹窗用的是自己的 sx，要单独加）。
- **截图**：`docs/img/dialogs-375-settings.png`（375 视口，已滚动到该字段）。

### P2-2　卡片设置：375 下操作区换行成 116px，吃掉小屏 15% 高度

- **现象**：`SiteSettingsModal` 底部操作区是 `justifyContent: "space-between"` 的三个按钮
  （删除 / 取消 / 保存）。375 视口下纸面只有 301px 宽，三个按钮换行成两排，操作区高 116px
  （1440 下是 36px 的一排）。同时操作区是 MUI v9 的 sticky 条，会盖在滚动区下沿——
  滚到底之后最后一项能正常露出（已验证），但小屏幕上「按钮占掉六分之一」的代价是实的。
- **根因**：三个按钮 + 左中分布列在 301px 里放不下；删除按钮文案偏长。
- **位置**：`src/components/SiteSettingsModal.tsx:951`（`DialogActions`）。
- **建议**：
  - xs 断点下把「删除」收成标题右侧的图标钮（与星标 Chip 并列），操作区只留 取消 / 保存，
    一行 36px 搞定；
  - 或给三个按钮在 xs 下用 `size="small"` + 短文案（「删」/「取消」/「保存」）。
- **截图**：`docs/img/dialogs-375-cardsettings.png`。

### P3-1　网站设置内容总高 3230px，375 下要滚 5 屏多

- **现象**：同一个弹窗里塞了 站点信息 / 外观 / 图标与缩略图 / 布局 / 隐私 / 离线缓存 / 关于 等
  七大块，实测内容区 `scrollHeight` 3230px、可视 606px。1440 下同样要滚近 5 屏。
- **建议**：要么按块折叠（`Accordion`，默认展开前两块），要么在标题下加一行锚点 chips
  （点一下滚到对应块）。这属于信息架构调整，工作量比前两条大，建议单独排期。

### P3-2　单卡删除没有二次确认，只有 8 秒撤销

- **现象**：卡片右键 → 删除，**直接删**（软删除进回收站），底部出带「撤销」的提示，8 秒后消失。
  批量删除、清空回收站都有 ConfirmDialog，唯独单卡删除没有。
- **评估**：软删除 + 可撤销是合理设计（回收站能兜底），但 8 秒窗口偏短，
  且「删错」往往发生在操作后一段时间（比如整理完一批才发现少了一张）。
- **建议**：二选一——把撤销窗口延长到 15~20 秒；或在设置里加「删除前确认」开关
  （默认关，保持现在的顺手）。不要改成「永远弹确认」：那会让批量整理变得极其难用。

### P3-3　个别弹窗的 maxWidth 与内容形态不匹配

- **记事本-设置（NotesSettingsDialog）**：`maxWidth='md'`（900px），里面是外观 / 编辑器 /
  分享列表 / 数据四类设置，900px 合理，但 375 下纸面 301px 时里面某些两列表单会挤
  （实测无溢出，但可预期地窄）。
- **记事本-版本历史**：`maxWidth='md'` 但内容只是版本列表，600px（sm）足够，
  900px 让列表行宽浪费。
- **AI 设置**：`maxWidth='xs'`（444px）却要放 开关 / 模型服务 / 凭据 / 测试连接 四组，
  1440 下内容是 444px 宽的一列，属最窄弹窗；建议升到 `sm`。
- 以上均为「不理想但不坏」，列入排期时按实际观感调整即可。

## 三、各弹窗优化后的目标行为（布局方案）

统一原则（本次实测全部满足，列为约束以防回退）：

1. **不溢出**：任何视口下纸面不超出视口（MUI 的 32px 容器边距 + maxWidth 已保证，
   不要引入 `fullScreen` 之外的固定宽度）。
2. **不横向滚**：弹窗内任何元素不产生横向滚动条；长 URL / 长 token 必须 `overflowWrap: anywhere`。
3. **操作区一行**：≤2 个主按钮时操作区保持一行 36px；≥3 个按钮或窄屏时，
   破坏性按钮移出操作区（标题区 / 图标钮），保证「取消 / 确认」永远一行可见。
4. **滚到底可见**：可滚内容滚到底后，最后一项完整露在操作区之上（已作为测量口径）。
5. **入口可达**：任何功能在 xs 视口都有入口（本次唯一违反的是记事本，见 P1-1）。

## 四、建议的实施顺序

1. **P1-1 记事本入口**（唯一的功能性缺陷，手机用户完全不可用）——半小时量级。
2. **P2-1 helperText 换行**（两行 sx，顺手在 dialogShell 里补统一规则）。
3. **P2-2 卡片设置操作区**（xs 断点重排，需回归 `SiteSettingsModal.dom.test.tsx`）。
4. P3 三项按观感排期，互不依赖。
