## 一、结论速览

- 第三批功能（分类备份、子文件夹拖放、正文标签）**代码与真机均已跑通**，本轮未发现 P0。

## 二、本轮查出的真实缺陷

### P1-1　文件夹「更多」菜单弹在屏幕左下角，与点击位置无关

- 位置：`src/components/NotesPage.tsx:399`　`anchorEl={undefined}`
- 根因：`FolderTagSection` 里维护了 `anchorRef`，但打开菜单时又被**显式置空**
  （`onClick={() => { setMenuId(item.id); anchorRef.current = null; }}`，第 370~372 行），
  随后 `Menu` 又传 `anchorEl={undefined}`。MUI 拿不到锚点就退化成锚到视口原点。
- 真机实测（1360×900，点击第一行文件夹的「⋯」）：
  ```
  MENU { items: ['新建子文件夹','移到根目录','重命名','删除'], x: 16, y: 724, w: 140 }
  ```
  菜单宽 140、高约 120，落在**屏幕左下角**，而点击点在左栏上部（y≈300 量级）——
  四个菜单项一个都没在鼠标附近，用户会以为点击失效。
- 为什么之前没发现：DOM 单测只断言菜单项存在，jsdom 没有布局，`getBoundingClientRect` 全 0，
  「飘到左下角」这种**纯视觉错位在单测里不可能暴露**。
- 修法：把 `anchorRef` 绑到那个 `IconButton` 的 ref 上，`anchorEl={anchorRef.current}`，
  并删掉打开时把它置空的那一行。

### P1-2　归档笔记被算进文件夹/标签的条数，但列表视图又把它们藏起来

- 位置：`src/API/methods/notes.ts:333`（`listFolders` 的 `COUNT`）与 `:459`（`listTags` 的 `COUNT`）
- 根因：后端计数子查询只判 `folder_id` / `tag_id`，**没有 `n.archived = 0`**；
  而前端 `NotesPage.tsx:953` 与 `:963` 的 `folderCounts` / `tagCounts` **明确排除了归档**。
- 后果：首屏先渲染接口返回的 `count`（含归档），本地重算后又变成不含归档的数字，
  **同一条文件夹行的数字会在首屏后悄悄变小**；两个来源长期不一致。
- 修法：后端两个 `COUNT` 子查询补 `AND n.archived = 0`，与前端口径统一（判据要只有一处定义）。

### P2-3　删标签后本地关联表没清，标签视图计数会虚高

- 位置：`src/hooks/useNotes.ts:428`（`removeTag`）
- 现象：`removeTag` 只 `setTags` 摘掉标签，**没有同步 `setNoteTags`**；
  而 `tagCounts` 正是靠 `noteTags` 里残留的 tagId 统计的。
- 后果：删掉一个标签后，该标签行确实消失，但它关联过的笔记在 `noteTags` 里仍留着那个 tagId；
  一旦**新建的标签复用了同一个 id**（或后端按名称合并返回旧 id），计数就会串到别的标签上。
- 修法：`removeTag` 成功后同步剔除 `noteTags` 各数组里的该 id（后端 `deleteTag` 已在事务里清关联，
  这里只是把本地视图对齐）。

### 复核过、**不是** bug 的两处（避免误改）

- 「未归类」判据：`filtered` 与 `viewCounts` 都用 `folder_id` 为空，两处一致；真机实测
  `全部3 / 未归类2`（有一条已被拖进文件夹），计数与列表吻合。
- 文件夹/标签互相选中时都会清掉对方（`setActiveFolder(null)` / `setActiveTag(null)`），
  不存在「两个筛选叠加成空列表」。

## 四、体验债（不阻塞功能，但明显不如 inkstone）

1. **重命名 / 新建文件夹标签仍用原生 `prompt()`**（`NotesPage.tsx:630 / 657 / 415`），
   样式突兀、部分 WebView 会拦；inkstone 全是自定义弹窗。
2. **拖放没有任何视觉反馈**：`onDragOver` 只设了 `dropEffect`，没有高亮目标行
   （真机实测拖动样式 `outline: none`），用户不知道能不能放、放在哪。
3. **无键盘可达性**：全屏 overlay 里 `Escape` 不关闭、Tab 不循环、返回键行为未定义；
   inkstone 的键盘路径明显更完整。
4. **子文件夹缩进只到 8 级**（`Math.min(item.depth, 8) * 1.25`），再深就完全看不出层级差异。
5. **三档视图在窄窗口直接隐藏**（`display: { xs: "none", sm: "flex" }`），
   小屏用户拿不到「预览模式」，只能被迫在源码态编辑。
6. **正文标签只追加不自动撤销**（第三批已知取舍，需在文档里对用户讲清）。

## 七、第四批 A 实施结果（三个缺陷已修）

| 缺陷 | 修法 | 验收结果 |
| --- | --- | --- |
| 菜单锚点为 `undefined` | 删掉 `anchorRef` 与「打开时置空」，改用 `useState` 存 `e.currentTarget`，`onClose` 一并清空 | **真机实测**：菜单 `x:97 y:356`，按钮 `x:108 y:345`，纵向差 11px（修前是 `y:724`，差 379px） |
| 计数含归档 | `listFolders` / `listTags` 的 `COUNT` 子查询补 `AND n.archived = 0`（含 `updateFolder` / `updateTag` 的回读，共 4 处）；`mock.ts` 同步 | **真实 SQLite 验证**（`harness/check-count-sql.mjs`）：活笔记 2 条 + 归档 1 条 + 他人 1 条 → 两条计数均为 2 |
| 删标签不清关联 | `useNotes.removeTag` 成功后按 id 剔除 `noteTags` 各数组；失败时连 `noteTags` 一起回滚 | 单测：删 id 7 后 `{1:[7,8],2:[7]}` → `{1:[8]}`，另一标签保留、笔记条目不消失 |

新增守卫三条：分类计数子查询必须带 `archived = 0`（源码级）、菜单锚点必须来自 `e.currentTarget`
且不得出现 `anchorEl={undefined}`、删除标签必须同步清理关联。

**验证**：类型检查、eslint 通过；全量单测、build、smoke 见交付说明。
菜单位置**只能真机验** —— jsdom 没有布局，这条已写进脚本注释与本报告，避免下次误以为单测能覆盖。
