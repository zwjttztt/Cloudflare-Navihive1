# 阶段 0–5 实施与验收清单（2026-10-11）

依据：《NaviHive 与 inkstone 复核及阶段计划》（同日 output/inkstone-review-20261011 报告）。本文件是那份计划里「阶段 0：基线与证据收口」的交付物，也是后续验收的对照表。

## 本批已实施（阶段 1 / 2 / 5 + 阶段 4 小件）

### 阶段 1：自动 WebDAV 备份附件闭环

- 服务端：`worker/notesBackup.ts` 备份升级 ZIP（`notes.json` + `attachments/<旧id>__<文件名>`），布局与前端导出 zip 完全一致；附件预算 24MB，超出跳过计数；租约在收集附件后续期；未配附件存储时回落旧 gzip JSON。
- 恢复端：`webdav/notes/download` 按文件头分流（PK→`zipBase64` 交前端走既有 ZIP 导入链路；其余走旧 JSON 解析）；前端 `NotesSettingsDialog.doRestore` 识别 `zipBase64` 走 `onImportFile`。
- 兼容：旧 `.json.gz` / 明文 JSON / 旧加密备份全部照旧可恢复；列目录过滤器已纳入 `.zip`；文件名前缀不变，保留策略照旧只清 auto 前缀。
- 测试：`tests/notesBackupZip.test.ts`（真 SQLite + 假 KV：布局、预算跳过、账号隔离、引用收集、文件名）。

### 阶段 2：数据集变更广播

- `useNotes` 暴露 `broadcastChange`；`saveOrder`、JSON/ZIP/Markdown 导入、网盘恢复（`onImportNotes` 包装）成功后统一广播。
- 语义不变：仍是「提示 + 用户确认刷新」，不自动替换草稿。

### 阶段 5：跨设备轮询增量同步（提示+列表收敛版）

- 服务端：`GET notes/changes?since=`（变更计数 + folders/tags/noteTags 快照 + 新游标）；`note_tombstone` 表（schema 16→17）在软删/彻底删/清空/到期清理时落墓碑；墓碑按回收站保留期随 `cleanupExpiredRows` 回收。
- 客户端：`src/utils/notesSync.ts`（按账号分桶的偏好与游标）；`useNotes` 轮询 effect（默认 120s，主标签心跳判活，页面隐藏跳过，首查只建基线）；变更 → `reload()` + 提示 + 广播。
- 明确不做：离线队列、自动合并草稿、实时推送（Realtime DO 维持不做）；游标为秒精度、比较用 `>=`，同秒内的变更可能被相邻两轮各看见一次（幂等 reload，预期行为）。

### 阶段 4 小件

- 备份租约：收集附件后追加续租（长任务最耗时的一段被覆盖）。
- 手动 FTS 重建、过期会话清理计数、附件删除重试：前一批已交付，本批只补 `notes/changes` 对墓碑表的依赖测试。

## 验收清单（人工/真机部分，待执行）

1. **备份恢复闭环（真网盘或本地 WebDAV 服务）**：新建含 2 张附件（其中一张被两条笔记引用）的笔记 → 手动备份 → 清空该账号数据 → 从网盘恢复 → 正文、附件字节、引用（新 id）、文件夹与标签全部正确；口令加密的 ZIP 备份走「弹口令框 → 恢复」同样成立；旧 JSON 备份仍可恢复。
2. **超预算路径**：附件总量 >24MB 时备份成功、运行记录显示「跳过 N」；恢复后缺失的图显示失败占位。
3. **广播**：两个同账号标签页，A 导入 JSON/ZIP、B 拖拽排序 → B/A 出现一次「刷新」提示，草稿不被覆盖。
4. **跨设备**：设备 A 改笔记、设备 B（≥120s 或手动等下一轮）列表自动收敛并提示；B 正在编辑同一条笔记时保存 → 409 冲突弹框照常出现（守卫未被削弱）。
5. **老部署兼容**：无 `notes/changes` 端点的部署打开记事本无报错、无轮询请求。
