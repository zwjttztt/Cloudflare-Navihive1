# docs 索引

`docs/` 下有 40 多份 markdown，其中 30 多份是**带日期的一次性报告**。它们不是垃圾，但
它们回答的是「某天我们看到了什么」，不是「现在该怎么做」。这份索引只做一件事：
**让你在三秒内找到该读的那一份**。

- 想知道**怎么运维**（部署 / 升级 / 回滚 / 备份）→ 看第二节，**先看「本文对应哪种形态」**。
- 想知道**为什么这么写代码**（样式、状态、踩过的坑）→ 看第一节，长期文档跟着代码一起维护。
- 想查**某次审计说了什么** → 看第三节，按月份倒序。**别把历史报告当现状**。

## 二、运维手册（出事时才翻，但请先读一遍）

⚠️ 这四份**互相有矛盾**，因为它们是不同时期、不同形态写的。**先认形态，再认文档**：

| 文档 | 本文对应哪种形态 | 什么时候该读 |
|---|---|---|
| `../deploy/selfhost.md` | **当前生产形态**：VPS 上的 Docker 容器（`navihive` + `navihive-upgrader`），宿主反代到 `127.0.0.1:8787` | 唯一的主手册。部署、环境变量、升级回滚、备份恢复、账号密钥、排障、安全须知全在这里。**遇到任何运维问题先翻它** |
| `../deploy/vps-redeploy-runbook-2026-10-16.md` | 同一形态，但走 **kPanel 面板**（粘贴 compose、面板点反代、面板配证书） | 只在「VPS 重装了、要从零再拉起一台」时读。它假设你没有 shell 习惯、全程用面板操作；日常升级不需要它 |
| `../deploy/nginx/README.md` | **裸机 Nginx**：自己装 Nginx + certbot，不用面板 | 只在「不用 kPanel、想自己写 Nginx 配置」时读。它与 kPanel 那份是**二选一**，不要同时照做（两边都会去抢 80/443） |
| `deploy/release.md` | 发布流程（本机 → GitHub → GHCR → VPS） | 每次发版都读。五步 + 一条「pull 前后比对 digest」的纪律 |

> 一句话区分：**kPanel 那份讲「怎么从零建一台」，nginx 那份讲「不用面板怎么写配置」，
> selfhost 那份讲「已经在跑了，接下来怎么维护」。** 日常只有 `selfhost.md` 和 `release.md`
> 会被翻开。

## 维护约定

- **新增一份带日期的报告，就在第三节对应月份加一行**，一句话结论 + 状态标记。不加的话
  下一个人（包括三个月后的你）仍然只会看见一堆文件名。
- 报告里的结论被推翻时，**不要删文件**，把状态改成 `已废弃` 并补一句「被谁取代」。
  历史报告的价值在于「当时为什么这么想」，删掉就没了。
- 长期文档改了就改，不用留日期；但**改动理由**要写进 CHANGELOG。
