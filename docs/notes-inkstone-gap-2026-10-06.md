## 三、bug 清单（本轮实查实修）

### P0 —— 线上功能整个不可用

**1. `POST /api/notes` 一律 500，新建笔记功能完全不可用**

- 位置：`src/API/methods/notes.ts:99`（`createNote`）
- 根因：`INSERT INTO notes` 列了 8 个字段（阶段三收尾加了 `folder_id`），
  值这一侧只给了 7 个（`?, ?, ?, ?, ?, COALESCE(...), ?`），
  SQLite 报 `table notes has 8 columns but 7 values were supplied`。
- 为什么没被发现：
  - `GET /api/notes` 完全正常，列表照常显示；
  - 现有守卫盯的是「占位符数 == bind 参数数」，这条**照样成立**（7 个 `?` 配 7 个参数，
    只是参数被错位绑给了后面的列）；
  - 路由层测试只验「路由把什么交给 api」，不执行 SQL；MockD1 按前缀匹配，不校验列/值个数。
- 状态：**已修** + 补了列数↔顶层值数守卫（`tests/noteSql.test.ts`）。

### P1 —— 静默丢数据 / 越权

**2. 回收站还原笔记丢 `folder_id` 与 `archived`**

- 位置：`src/API/methods/recycle.ts`（`reinsertNote`）
- 现象：归档笔记还原后弹回「全部」视图；归了文件夹的笔记掉回「未归类」。
- 迷惑性：删笔记时进回收站的是 `SELECT *` 的完整行，字段**在里面**，
  只是还原时少写一列 → 用户看着像还原成功，其实在丢状态。
- 状态：**已修**（INSERT 补两列 + bind 补两个值），加了守卫。

**3. 标签关联在删除时既没存也没清**

- 位置：`notes.ts`（`deleteNote`）
- 现象：删笔记后 `note_note_tag` 留着指向已删笔记的悬空行，还占着左栏标签计数；
  还原换了新 id，标签再也接不回来。
- 状态：**已修**（一并存 `tagIds`、一并清关联；`reinsertNote` 写回新 id，写前确认标签还活着）。

**4. `listNoteTags` 越权 + 全表扫**

- 位置：`notes.ts`（`listNoteTags`）
- 现象：`SELECT note_id, tag_id FROM note_note_tag` —— 这张表**没有 user_id 列**，
  归属只能靠 `JOIN notes` 判定。不加 JOIN 就是跨账号把别家的 (noteId → tagId) 拉回前端。
- 状态：**已修**（加 `JOIN notes` + `scopeSql(true)`，顺带挡掉悬空行）。

**5. `deleteFolder` 不在事务里**

- 位置：`notes.ts`（`deleteFolder`）
- 现象：先删文件夹再清 `notes.folder_id`，中途失败就留下悬空 `folder_id` ——
  那几条笔记在左栏任何文件夹视图里都点不出来，看着像被删了。
- 状态：**已修**（两条语句进同一个 `db.batch`，并调整为先清关联再删文件夹）。

**6. `listNotesByTags` 绑定参数顺序错**（死代码，前端未调用）

- SQL 里账号条件写在 `WHERE … IN (…)` **之前**，而 `scopeParams` 把账号 id 追加到**末尾**。
- 留着就是个雷：哪天有人接上去，症状是 500 且极难定位。
- 状态：**已修**（改 `bind(...scopeParams([]), ...ids)`）。

### P2 —— 界面语义 / 体验

**7. 「未归类」视图判据错了，与「全部」完全等价**

- 位置：`NotesPage.tsx`（`filtered` 与 `viewCounts`）
- 根因：筛的是 `site_id`（没挂在站点上），而记事本**根本没有「把笔记挂到站点」的入口**，
  `site_id` 永远是 null → 该视图恒等于「全部」（实测左栏两个计数一模一样）。
- 状态：**已修**（改按 `folder_id` 判，视图与计数同步改，并加了「两处判据不许各写各的」用例）。

**8. 文件夹 / 标签是「有后端、没入口」**

- `onAssignTags` 从 `App.tsx` 一路传到 `NotesPage` 的 props，**但从没被调用**；
  界面也没有任何地方能把笔记归入文件夹。结果：两个视图永远是空的。
- 状态：**已修**（每行 hover 出「⋯」菜单：收藏 / 归档 / 归入文件夹 / 编辑标签 / 删除；
  列表行显示标签徽章）。

**9. 拖分隔条的比例存不回去**

- 位置：`NotesPage.tsx`（`startSplitDrag` 的 `onUp`）
- 根因：写的是 `String(readSplitRatio())` —— 那是**从 localStorage 读**，
  读回来必然是拖动前的旧值；而且 `onUp` 是 mousedown 那一刻挂的闭包，
  读 `splitRatio` state 也拿不到最新值。
- 现象：拖完松手，刷新页面宽度弹回去（用户视角「拖不动」）。
- 状态：**已修**（新增 `splitRatioRef`，`onMove` 跟住最新值，`onUp` 读 ref）。

### P3 —— 本轮发现但未修（见下一步计划）

- 编辑器仍是原生 textarea，inkstone 用 CodeMirror：行号 / 语法高亮 / 撤销栈 / 移动端选区都缺。
- 全文搜索只有列表内过滤，没有独立搜索视图。
- 状态栏没有「创建于…」。
- `prompt()` 用于重命名 / 新建文件夹标签：能用但样式突兀，且部分 WebView 下会被拦。
- 导入备份不还原 `folder_id` / `archived`（`transfer.ts:595` 的 INSERT 也没这两列）。
- 线上有 2 条测试残留笔记（`$11111…`、空笔记），是排查过程中写进去的，**需要你确认后清理**。
