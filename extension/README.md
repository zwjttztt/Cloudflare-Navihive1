# 浏览器扩展：一键收藏

> ⚠️ **实验性功能**：这个扩展是仓库里的旁支，**不在 CI 里**（没有构建、没有 lint、
> 没有类型检查，也没有真机安装验证）。它靠一条深链契约与主站对接 ——
> 那条编解码契约有 `tests/extensionDeepLink.test.ts` 双向钉住（字符集一改就会红），
> 但「扩展在某个浏览器里能不能装、能不能读标签页」只能人工验。
> 用它之前请先看一眼下面的「已知限制」。

把正在看的网页**顺手**存进自己的 NaviHive 导航站：自动带入标题、链接和 favicon，
点「保存」就跳到你的站点并打开「新增站点」弹窗 —— 你只需要选分组、确认。

> 书签**批量**导入不用它：站内「更多选项 → 书签导入」已经支持（HTML 书签文件）。
> 这个扩展解决的是另一头：**浏览时遇到一个想留的页面**，不用回到站内手打 URL。

## 已知限制（实验性功能的边界）

- 只在 Chromium 系（Chrome / Edge / 其它 MV3 浏览器）上人工验过；Firefox / Safari 未验。
- 不是商店分发，要手动「加载已解压的扩展程序」。
- 站点地址只存在本机 `storage.local`，换机要重填一次。
- 深链里的图标只带 favicon 的 URL，主站不会替你抓取 —— favicon 取不到时图标为空，
  站内有自己的图标补全逻辑。

## 安装（开发者模式，两个浏览器都一样）

不需要构建、不需要 npm —— 就是一个文件夹。

1. 打开 `chrome://extensions`（Edge 是 `edge://extensions`），右上角打开「开发者模式」
2. 点「加载已解压的扩展程序」，选中本仓库的 `extension/` 目录
3. 点扩展图标（或按 `Alt+Shift+N`），填一次你的导航站地址，之后会记住

发布到应用商店前不用改代码；要改图标就往 `extension/` 放 PNG 并在 `manifest.json`
里加 `icons` / `action.default_icon`。

## 它是怎么工作的

```
扩展                                     你的站点
├─ 读当前标签页的 title/url/favicon
├─ 拼 https://<站点>/?add-site=<base64url>
└─ 新标签页打开 ────────────────────────► 认出 add-site 参数
                                          └─ 打开「新增站点」弹窗并填好字段
```

**扩展不持有任何凭据。** 它不去调写接口 —— 写接口要带 httpOnly cookie 与 CSRF 校验，
扩展想复用就得申请 cookies 权限、自己处理跨域和令牌过期，等于把鉴权面扩大一圈。
交给已登录的页面去做，没登录时也只是正常跳到登录页，行为可预期。

站点侧的实现在 `src/utils/addSiteDeepLink.ts`（参数名 `add-site`、base64url 编码），
两边改编码格式必须同步。用完参数会立刻从地址栏抹掉，刷新不会重复弹窗。

## 权限说明（为什么只要这两个）

| 权限         | 用途                             |
| ------------ | -------------------------------- |
| `activeTab`  | 只在**你点扩展那一刻**读当前标签页的标题与地址 |
| `storage`    | 记住你的导航站地址（存在本机，不上传）  |

没有 `cookies`、没有 `<all_urls>`、没有后台常驻脚本 —— 扩展不读你别的页面，
也不在你不点它的时候做任何事。

## 常见问题

- **点了没反应 / 提示读不到标签页**：`chrome://`、扩展商店、空白页这些受限页面上
  拿不到 URL，手动填一下即可。
- **打开站点没弹窗**：确认地址栏里带了 `?add-site=`；没有的话多半是弹窗已经兑现过
  一次（参数被抹掉了），回到扩展再点一次即可。
- **存到了错误的分组**：弹窗里的分组默认取「你正在看的那个」，保存前可以改。
